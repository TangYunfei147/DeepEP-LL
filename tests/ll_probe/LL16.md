# LL：每机16卡

本分支的生产低时延 dispatch/combine 以16个连续全局rank组成一个物理主机组：`host=rank/16`、`local=rank%16`。单机EP16是一个组，双机EP32是两个组；原有EP64/128等受支持规模继续按每机16卡组织。所有参与节点必须使用同一提交重新构建，不可混用旧8卡分组wheel。

## 算法与同步

- 分组常量位于`csrc/kernels/dispatch/low_latency/common/ep_memory_server_dedup_protocol.h`。dispatch分类、去重、组级发送顺序及Host UB预算使用同一常量。
- 单机EP16所有路由都属于本组，去重路径没有跨组FIRST_HOP。跨机时同一目标16卡组的多条路由可合并首跳并中转。现有按每rank容量选择去重的阈值保持不变。
- combine按16-rank组选择DIRECT和partial任务。核56..63仍负责ready通知，每核通知两个本组peer；每个接收核等待16个32B标志。既有512B ready行恰好容纳16个标志，准备阶段的8份发布是通知核数量，不是设备组大小，保持不变。
- 数据包的8字节索引、32B标志、8条流水lane等不是拓扑，保持原协议。
- `csrc/runtime/udma_peer_masks.hpp`的8路QP映射服务非LL的HT dispatch；LL payload使用MTE映射，不使用该QP发送路径。保持HT kernel与QP admission一致，不能把共享运行时的所有8一律替换成16。网络探针仍查询实际Session的UDMA通道，并单独验证MTE可达性。
- metadata探针的参考分类与UB预算同步改为16卡组；其逻辑分区仍不代表启动了16个设备rank。

## Git获取与构建

切换并更新`experiments/ll-four-layer-probes`。从仓库根目录，先按当前机器配置CANN环境，然后执行：

```bash
git submodule update --init --recursive --depth 1
unset SHMEM_ROOT CATLASS_ROOT
source scripts/project_env.sh
python scripts/build_shmem.py
export DEEPEP_NPU_ARCH=Ascend950
export LD_LIBRARY_PATH="$PWD/third-party/shmem/install/shmem/lib:${LD_LIBRARY_PATH:-}"
python -m pip install -r requirements-build.txt
python -m pip install -v --force-reinstall --no-build-isolation --no-deps .
bash tests/ll_probe/build_profile_bridge.sh
```

首次构建使用上述SDK命令；若仓内已有SDK，使用`python scripts/build_shmem.py --if-needed`校验并复用，避免覆盖已有产物。

外部CANN环境由用户配置`CANN_ENV`或提前加载。脚本从自身位置定位工程，日志、缓存、临时文件及结果留在工程内。构建或pip缓存不得改到其他SDK目录。

## 单机目标验收

CPU计划不扩展设备、不初始化NPU，可先运行：

```bash
bash tests/ll_probe/run_ll16.sh --plan --num-tokens 1 8 33
```

以下`--target-run`只由用户在目标机器执行，显式启用16张卡。`LL_TARGET_DEVICES`可指定16个不同物理设备编号，默认0..15。不要在A5运行：

```bash
bash tests/ll_probe/run_ll16.sh --target-run --check
```

默认检查B=1/8/33、BF16/FP16/FP8、三次combine复用，覆盖容量32两侧的执行路径。完整验证通过后再测量：

```bash
bash tests/ll_probe/run_ll16.sh --target-run --profile \
  --num-tokens 1 2 4 8 16 32 64 --hidden 7168 --num-experts 128 --num-topk 8
```

正式性能仍遵循[PROFILING.md](PROFILING.md)：10次预热、100次采集、每次Exp和scalar all_reduce、各kernel/task最后50条独立统计。参考Exp大缓冲保持默认；Event/API/task不互相替代。

每rank仍需8GiB对称workspace，全部peer须支持MTE地址映射。默认整个运行1800秒超时，可通过`LL_TIMEOUT_SECONDS`调整；超时会终止本次进程组，结果视为失败，不自动重试或纳入性能统计。

## 跨机目标验收

每台机器本地启动16进程，节点编号从0开始。两机共32rank，示例将`HOST0_IP`替换为首机可达地址，两台使用相同端口及参数：

```bash
# 第一台
bash tests/ll_probe/run_ll16.sh --target-run --check \
  --num-nodes 2 --node-rank 0 --master-addr HOST0_IP --master-port 29500 --shmem-port 29501
# 第二台
bash tests/ll_probe/run_ll16.sh --target-run --check \
  --num-nodes 2 --node-rank 1 --master-addr HOST0_IP --master-port 29500 --shmem-port 29501
```

EP64/128对应4/8台。每台16个连续rank，同节点的LOCAL_RANK为0..15；torchrun须设置`--nproc-per-node=16`。启动检查会拒绝旧的每机8进程配置。跨机MTE可达性仍须由实际互联验证，不能用同机IPC实验替代。

验收时确认所有rank正常退出、dispatch内容/专家计数正确、combine加权结果及重复调用正确，并保留所有节点日志、提交号和结果目录。A5仅运行设备0/1探针与CPU/编译检查，不能代替本节完整LL验收。
