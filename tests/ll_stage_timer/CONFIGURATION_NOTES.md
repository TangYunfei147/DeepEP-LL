# 配置与冗余维护注意事项

## 当前默认行为

- NDR分支固定编入HNS_1825能力，SDK准备与wheel构建不再要求重复选择RDMA。旧DEEPEP_LL_RDMA=ON仍兼容，OFF或其他旧值给出弃用提示，不再作为构建开关。需要MTE对照使用运行时--backend mte；无RDMA能力的构建使用泛化分支。
- 两分支的python scripts/build_shmem.py均自动校验后复用已有SDK。NDR默认HNS_1825；泛化默认MTE，也接受验证通过的HNS能力超集，不自动应用RDMA源码补丁。
- 共同LL入口tests/ll_stage_timer/run.py和直接LL ST按分支选择后端；历史shell后端状态不会覆盖入口默认。泛化显式rdma请求报错；显式mte仍可对照。旧tests/ll_rdma/run_ll.py委托共同入口。
- 公共Runtime/Session保持原mte默认，不能仅凭8GiB或token上限猜测后续调用一定是LL。已确认LL的入口设置后端；Elastic省略page参数时从明确后端推导，rdma普通页，其他模式保持原1GiB页。显式rdma加1GiB页仍拒绝，不静默更改用户选择。
- LL测试默认普通页；专家capture隐含阶段capture，不要求同时写两个开关。本地进程数可从明确设备列表推断，配置文件/命令行指定数量仍优先并接受一致性检查。

## 以后如何避免同类问题

1. 同一事实只让用户选择一次。分支已确定的编译能力不再层层传环境变量、CMake选项和runner参数；内部编译宏可以作为实现细节保留。
2. 将能力、运行选择和实验变量区分：固定分支能力自动确定；MTE对照、timer开关、observe/drain和实际设备列表仍由用户选择。G可作为跨分支比较变量，不新增跨分支G一致性要求。
3. 派生参数由拥有完整语义的入口推导，不在通用API用容量、形状等启发式猜用途。保持非LL调用兼容，不用简化配置为理由静默改变执行路径。
4. SDK复用比较所需能力与可信身份，不要求整份配置字典逐字相等。必须继续校验锁定revision、CANN版本/时间戳、目标、完整源码指纹、headers与库哈希。只接受已知完整三处72-QP补丁的HNS能力超集；未知修改、部分补丁、损坏产物不可复用。
5. 区分冗余选项与必要保护：SDK身份不匹配仍要求停止使用者后显式--rebuild，未知源码修改仍要求明确授权；ABI、同作业内rank一致性、设备可见性、16连续rank拓扑与跨机preflight继续保留。
6. 旧入口应委托共同实现，避免复制默认值和校验。每次更新同时审计当前指南、简化示例、配置文件优先级、旧环境残留以及其他工作目录调用。
7. 所有缓存/日志/临时文件从工程位置定位；含空格路径迁移须回归。其他任务的kernel试验改动保留本地，提交明确列出本任务文件。
